# План дообучения локальной модели

На хакатоне GPU нет, поэтому сделан конвейер данных; само обучение — следующий шаг.

## 1. Данные

Источник — диалоги из Postgres (`dialogs` + `messages`), выгрузка `backend/cmd/export-dataset`:

```bash
cd backend
go run ./cmd/export-dataset -out dataset.jsonl                  # все диалоги
go run ./cmd/export-dataset -only-operator -out gold.jsonl     # только с ответом оператора
# -db postgres://...   (по умолчанию $DATABASE_URL или localhost:55433)
```

- `patient` → `user`, `bot` и `operator` → `assistant`.
- Ответ оператора — эталон: если оператор ответил после бота на ту же реплику пациента, ответ бота выбрасывается.
- Подряд идущие реплики одной стороны склеиваются; приветствие до первой реплики пациента и последняя реплика пациента без ответа отбрасываются; диалоги короче 2 реплик пропускаются.
- Основной обучающий набор — `gold.jsonl` (диалоги, исправленные операторами). Ответы бота без правки — только как дополнение после проверки.

**Анонимизация** (`anonymize.go`, покрыта тестами на ru/kk) применяется к каждому сообщению:
e-mail → `[EMAIL]`, карта (13–19 цифр, группы по 4) → `[КАРТА]`, ИИН (12 цифр) → `[ИИН]`,
телефон (+7/8 и 10 цифр) → `[ТЕЛЕФОН]`, дата рождения `12.03.1990` → `[ДАТА]`,
имя после «меня зовут / мое имя / менің атым / атым / my name is» → `[ИМЯ]`.

Регулярки не ловят всё (адреса, имена без вводной фразы, фамилии врачей). **Перед обучением — ручная проверка** всего файла двумя людьми: `grep -nE '[0-9]{6,}|@|ул\.|көш'`, чтение выборки, удаление диалогов с диагнозами/назначениями в ответах.

## 2. Формат

JSONL, одна строка — один диалог (формат OpenAI / LLaMA chat):

```json
{"messages":[{"role":"system","content":"Ты — ассистент контакт-центра клиники MedHub..."},
 {"role":"user","content":"болит зуб"},{"role":"assistant","content":"Запишу вас к стоматологу-терапевту..."}]}
```

Разбиение: 90% train / 10% val, по диалогам (не по репликам).

## 3. Метод

QLoRA (4-bit база + LoRA r=16, alpha=32, dropout 0.05, 2–3 эпохи, lr 2e-4, max_seq_len 2048).
Базовая модель: `Qwen2.5-7B-Instruct` (рус/англ, уже используется в LM Studio) или `KazLLM-8B` (для казахских ответов, `LLM_MODEL_KK`).
Нужно ~16–24 ГБ VRAM (RTX 4090 / A10 / L4, либо арендованный GPU).

```bash
pip install unsloth
python train.py   # FastLanguageModel.from_pretrained("unsloth/Qwen2.5-7B-Instruct-bnb-4bit", load_in_4bit=True)
                  # get_peft_model(r=16, lora_alpha=32, target_modules=["q_proj","k_proj","v_proj","o_proj","gate_proj","up_proj","down_proj"])
                  # SFTTrainer(train_dataset=load_dataset("json", data_files="gold.jsonl")) — loss только на assistant
```

Альтернатива — axolotl (`type: chat_template`, `field_messages: messages`, `adapter: qlora`).

## 4. Экспорт в LM Studio

```bash
# unsloth: слить адаптер и сразу в GGUF
model.save_pretrained_gguf("medhub-qwen7b", tokenizer, quantization_method="q4_k_m")
# или llama.cpp:
python llama.cpp/convert_lora_to_gguf.py lora_out --base Qwen2.5-7B-Instruct --outfile medhub-lora.gguf
```

Готовый `.gguf` положить в `~/.lmstudio/models/medhub/medhub-qwen7b/`, загрузить в LM Studio и указать его id в `LLM_MODEL` (или `LLM_MODEL_KK`). Бэкенд менять не нужно: API тот же, JSON-схема с `strict: true` по-прежнему ограничивает вывод.

## 5. Оценка

Прогон набора команды из 25 сценариев (ru/kk) на базовой и дообученной модели:

- точность срочности (green/yellow) и специальности (id из каталога) — дообученная модель не должна быть хуже базовой;
- доля невалидного JSON (fallback на оператора);
- ручная проверка ответов: нет диагнозов, назначений, выдуманных цен.

**Red остаётся 100% детерминированным в коде** (`triage_rules.json`, проверка до вызова LLM) и не зависит от модели. Если red-сценарии проходят не на 100% — это ошибка правил, а не модели. Эти тесты (`go test`) должны проходить без изменений.

## 6. Чему модель НЕ должна учиться

- Диагнозам и назначениям лечения/лекарств — такие ответы операторов удаляются из набора при ручной проверке.
- Ценам — цены всегда берутся из `catalog.json`; числа цен в ответах перед обучением заменять или удалять диалог.
- Расписанию и именам врачей — их даёт каталог, иначе модель будет «помнить» устаревшие данные.
- Решению red — только код.
