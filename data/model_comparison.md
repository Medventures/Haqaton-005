# Сравнение локальных моделей

Проверка выполнена через API на 25 диалогах из `test_dialogs.json`. Обе модели запускались с контекстом 4096 и `parallel=1`; Qwen3-4B проверен на CPU, а Qwen2.5-7B — на CPU. Контекст 2048 у Qwen3-4B оказался мал для промпта с каталогом: LM Studio вернул `Context size has been exceeded`.

| Модель | Urgency | Specialty | Status | Все проверки urgency + specialty |
|---|---:|---:|---:|---:|
| Qwen2.5-7B-Instruct (`qwen/qwen2.5-7b`) | 21/25 (84%) | 25/25 (100%) | 25/25 (100%) | 46/50 |
| Qwen3-4B-2507 (`qwen/qwen3-4b-2507`) | 22/25 (88%) | 23/25 (92%) | 25/25 (100%) | 45/50 |

Для этой ветки выбрана Qwen3-4B-2507: она лучше подходит для казахских диалогов. По прежнему прогону на 25 сценариях urgency 22/25 (88%), specialty 23/25 (92%). Qwen2.5-7B имеет более высокую specialty точность 25/25 (100%), но пропустила казахский yellow-сценарий с температурой ребёнка. Qwen3 поддерживает 119 языков и диалектов, включая казахский; смотрите модельные материалы Qwen перед развёртыванием.

## Ошибки, переданные бэкенду

- Qwen2.5-7B дала green для боли в животе с тошнотой, головокружения в течение недели, жжения при мочеиспускании и казахского сообщения о температуре ребёнка.
- Qwen3-4B дала green для первых трёх yellow сценариев, неверно выбрала кардиолога вместо терапевта при температуре и ошиблась в двух specialty.
- Обе модели правильно обработали все шесть red сценариев; red-ответы формируются детерминированно до LLM.
- Сценарии yellow требуют сверки с врачом: результат показывает, что текущие правила и промпт пока не дают надёжной оценки срочности.

Полные таблицы фактических ответов: `test_results_qwen2_5_7b.txt` и `test_results_qwen3_4b.txt`.
