# MedHub Clinic — чат-бот подбора услуг клиники

**Команда:** _заполнить: название и участники_

## Проблема

Пациент не знает, к какому врачу идти со своей жалобой, сколько стоит приём и когда есть свободное время. Администраторы тратят время на однотипные вопросы, а срочные случаи (боль в груди, признаки инсульта) могут потеряться в общем потоке.

## Решение

Чат-бот на сайте клиники на русском, казахском и английском языках (язык определяется по сообщению, каталог переведён):

1. **Триаж срочности** (green / yellow / red).
   - **red** — детерминированная проверка каждого сообщения по фразам из `triage_rules.json` **до** вызова LLM. Бот сразу отвечает «Срочно звоните 103» (кнопка `tel:103`), подбор услуг прекращается, диалог уходит в начало очереди оператора.
   - **yellow / green** — определяет LLM (поле `urgency` в схеме извлечения); yellow-фразы из `triage_rules.json` передаются в промпт как ориентир. При yellow бот советует обратиться за помощью в ближайшее время и предлагает связаться с оператором.
   - Уровень диалога только повышается, никогда не понижается.
   - **Акушерско-гинекологический контекст.** Флаг беременности ставит код по фразам в любом сообщении («беременна», «я на 32 неделе», «жүктімін», «30 аптадамын»; отрицания вроде «не беременна» учитываются) или LLM (`pregnant`, `gestation_weeks`). Раз выставленный флаг не снимается. При флаге red-проверка добавляет правила `red_if_pregnant` и идёт по **всем** сообщениям пациента: «тянет низ живота», а потом «я на 32 неделе» → red. Кнопки у беременной при red: «Вызвать скорую — 103» и «Срочно связаться с оператором». При боли внизу живота, кровянистых выделениях, тошноте или задержке без упоминания беременности бот один раз спрашивает «Есть ли у вас беременность или её вероятность?» (решает LLM, плюс страховка по фразам `ask_pregnancy_if`).
2. **LLM-извлечение** через LM Studio (OpenAI-совместимый API, `response_format: json_schema`, `strict: true`): язык, намерение, специальность (только id из каталога), нужно ли уточнение, срочность, summary. Если ответ не парсится как JSON — один повтор, затем безопасный fallback: `urgency=yellow`, `intent=operator` (диалог уходит оператору).
3. **Уточнения** — на жалобу бот сначала задаёт уточняющий вопрос и только после ответа показывает срочность и услуги (red — сразу, без вопросов). Не больше 2 уточнений за диалог, потом бот подбирает специальность или передаёт оператору.
4. **Подбор** — услуги с ценами и врачи со свободными слотами берутся кодом из `catalog.json`, LLM только формулирует ответ по этим данным (без диагнозов, лечения и выдуманных услуг/цен).
5. **База знаний** (`knowledge.json`, ru/kk/en) — практические вопросы: адрес, часы работы, запись и отмена, оплата и ОСМС, документы, подготовка к анализам и УЗИ, результаты. Ответ берётся из базы как есть (без переписывания моделью), к подготовке прикладываются карточки услуг. Цены — только из каталога.
6. **Передача оператору** — по просьбе пациента, при red, при ошибке ИИ или если специальность определить не удалось. Обращение содержит summary: что хотел пациент, что выяснено, почему передано.

### Дообучение модели

Для дообучения на обезличенных диалогах контакт-центра есть выгрузка `backend/cmd/export-dataset` (JSONL в chat-формате, ответы оператора — эталон) с анонимизацией телефонов, ИИН, e-mail, карт, дат рождения и имён. План обучения (LoRA на Qwen2.5-7B / KazLLM-8B, экспорт в GGUF для LM Studio, оценка) — [`docs/FINETUNE.md`](docs/FINETUNE.md). Само обучение на хакатоне не проводилось: нужен GPU с 16–24 ГБ.

## Демо

- Лендинг: https://medhub-clinic.vercel.app
- Чат пациента и страница оператора (`/operator`, вход `operator1 / operator1`) на время хакатона открыты через временный туннель — ссылка на лендинге в кнопке «Открыть чат». Локально всё поднимается одной командой (см. ниже).

## Запуск

Требования: Docker + Docker Compose, [LM Studio](https://lmstudio.ai) на хост-машине.

1. В LM Studio загрузите модель (например, `qwen2.5-7b-instruct`) и запустите сервер: **Developer → Start Server** (порт 1234).
2. ```bash
   cp .env.example .env   # укажите LLM_MODEL = id модели из LM Studio
   docker compose up --build
   ```
3. Чат пациента: http://localhost:5180, оператор: http://localhost:5180/operator
4. API: http://localhost:8088, OpenAPI: http://localhost:8088/api/openapi.yaml

Переменные окружения (`.env`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_BASE_URL` | `http://host.docker.internal:1234/v1` | OpenAI-совместимый API (LM Studio) |
| `LLM_MODEL` | — | id модели в LM Studio |
| `JWT_SECRET` | `change-me-hackathon` | секрет подписи JWT |
| `LLM_MODEL_KK` | — | (опц.) отдельная модель для ответов на казахском, например KazLLM; разбор (JSON) остаётся на `LLM_MODEL` |
| `ASK_FIRST` | `true` | `false` — показывать срочность и услуги сразу, без первого уточняющего вопроса |
| `STATIC_DIR` | — | (опц.) папка собранного фронтенда: бэкенд раздаёт его сам, без nginx |

На Linux доступ из контейнера к хосту обеспечивает `extra_hosts: host.docker.internal:host-gateway` в `docker-compose.yml`. LM Studio должен слушать не только `127.0.0.1` (в настройках сервера — «Serve on Local Network»).

### Проверка через curl

```bash
B=http://localhost:8088
TOK=$(curl -s -XPOST $B/api/auth/patient | jq -r .token)
curl -s -XPOST $B/api/chat -H "Authorization: Bearer $TOK" \
  -d '{"message":"Третий день болит горло и заложен нос"}' | jq
# продолжить диалог: добавить "dialog_id" из ответа

OP=$(curl -s -XPOST $B/api/auth/login -d '{"username":"operator1","password":"operator1"}' | jq -r .token)
curl -s $B/api/operator/queue -H "Authorization: Bearer $OP" | jq
```

Операторы (захардкожены для демо): `operator1 / operator1`, `operator2 / operator2`.

### Тесты

```bash
docker compose up -d db          # тестам нужен Postgres (создают отдельную БД clinic_test)
cd backend && go test ./...
```

Тесты чат-логики (`backend/chat_test.go`) идут через HTTP API с настоящим Postgres и фейковым OpenAI-совместимым LLM-сервером: red без вызова LLM (в т.ч. на ответе-уточнении), лимит 2 уточнений, retry и безопасный fallback, специальности только из каталога, врачи только со слотами, уровень только растёт, сортировка очереди, бот молчит при операторе, доступ patient/operator, ответ и закрытие оператором. Без Postgres тесты пропускаются.

## API

| Метод | Путь | Роль | Назначение |
|---|---|---|---|
| POST | `/api/auth/patient` | — | анонимная сессия пациента (JWT) |
| POST | `/api/auth/login` | — | вход оператора |
| POST | `/api/chat` | patient | сообщение пациента → ответ бота, услуги, врачи, срочность |
| POST | `/api/chat/operator` | patient | кнопки «Связаться с оператором» / «Срочно связаться с оператором» |
| GET | `/api/dialogs/:id` | patient / operator | диалог; пациент — только свой, оператор — только переданные |
| GET | `/api/operator/queue` | operator | очередь: red → yellow → green, затем по времени |
| POST | `/api/operator/reply` | operator | ответ в диалог; `close: true` закрывает обращение |
| GET | `/api/catalog` | — | каталог |
| GET | `/api/openapi.yaml` | — | OpenAPI 3 описание |

## Структура проекта

```
catalog.json         специальности, услуги, врачи со слотами (загружается при старте)
triage_rules.json    red / red_if_pregnant (рус/каз/англ), yellow-ориентиры для LLM, фразы для вопроса о беременности
docker-compose.yml   postgres + backend + frontend
DESIGN.md            дизайн-правила интерфейса
AGENTS.md            инструкции для ИИ-агентов, работающих с фронтендом
frontend/            React + Vite + TS: чат пациента (/) и рабочее место оператора (/operator), i18n ru/kk/en
knowledge.json       база знаний клиники (демо-данные): практические вопросы, подготовка к исследованиям
docs/FINETUNE.md     план дообучения локальной модели
backend/cmd/export-dataset/  выгрузка обезличенных диалогов для дообучения
landing/             лендинг (React + Vite + TS, motion), деплой на Vercel
backend/
  main.go            роутинг, конфиг
  triage.go          нормализация и red-триаж (+ triage_test.go)
  llm.go             клиент LM Studio, JSON-схема и промпт извлечения
  chat.go            пайплайн сообщения, очередь и ответ оператора
  db.go              схема Postgres: dialogs, messages, tickets
  auth.go            JWT, роли patient / operator
  catalog.go         загрузка каталога
  openapi.yaml       описание API
```

Известные ограничения:
- Запись к врачу — заглушка, слоты не бронируются.
- Red-правила — список фраз; они не заменяют медицинскую оценку. Сообщение проверяется по частям, отрицание, давность и анамнез («боли в груди нет», «у папы был инфаркт в прошлом году», «кеудем ауырмайды») исключаются через `red_exclude` — такие сообщения оценивает LLM. Списки должен проверить врач.
- Качество ответов на казахском зависит от модели: Qwen2.5-7B понимает казахские жалобы, но пишет с ошибками; фиксированные тексты (103, вопрос о беременности, передача оператору) написаны вручную.
- Операторы захардкожены, пациент — анонимная сессия.
